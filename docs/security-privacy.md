# 安全与隐私

状态：Active

本文描述当前代码的安全与隐私边界，不替代法律审查或微信、高德等平台的正式协议。

## 1. 数据流

### 1.1 用户位置

当前位置用于：

- 在地图中显示用户位置和查询基准点。
- 逆地理编码当前城市。
- 查询附近公共厕所和地铁站。
- 计算展示距离。
- 发起路线或外部导航。

当前代码没有数据库，也没有把用户位置、搜索历史或导航记录持久化到后端。后端收到坐标后会把坐标发送给高德 Web Service 完成业务请求，因此“未在本项目存储”不等于“没有第三方处理”。

### 1.2 地图与第三方服务

- 网页：高德 JS API 和高德 Web Service。
- 微信小程序：微信 `map` 组件/腾讯地图底图；业务查询经后端使用高德 Web Service。
- Android：高德地图与定位 SDK；业务查询经统一后端。

正式隐私说明应列出这些第三方处理者及用途，具体法务文本待确认。

## 2. 权限

### 2.1 微信小程序

`WhereToPoop/miniprogram/app.json` 声明：

- `scope.userLocation`
- `requiredPrivateInfos: ["getLocation"]`

说明文本为“用于查找你附近的公共厕所和地铁站厕所信息”。代码仅在启动和用户点击重新定位时调用 `wx.getLocation`，没有后台持续定位。

辅助审核材料曾把定位描述为“用户主动点击定位或查找后调用”，但当前 `pages/index/index.ts` 在页面挂载后自动执行定位。正式隐私保护指引和审核说明必须按当前行为复核，不能继续沿用不一致表述。

### 2.2 Android

`WhereToPoop_apk/app/src/main/AndroidManifest.xml` 声明：

- `INTERNET`
- `ACCESS_NETWORK_STATE`
- `ACCESS_WIFI_STATE`
- `CHANGE_WIFI_STATE`
- `ACCESS_COARSE_LOCATION`
- `ACCESS_FINE_LOCATION`

定位客户端配置为单次高精度定位。`CHANGE_WIFI_STATE` 是否为实际功能必需尚未确认，应在发布前按最小权限原则复核。

Android 当前设置 `android:allowBackup="true"`。应用没有用户数据库，但仍应评估发布版是否需要关闭备份。

## 3. 密钥管理

| 密钥 | 位置 | 暴露模型 | 必须限制 |
| --- | --- | --- | --- |
| `AMAP_WEB_SERVICE_KEY` | 后端 `.env` | 仅服务器 | 服务白名单、配额监控、定期轮换 |
| `AMAP_JS_KEY` | 后端 `.env`，经 `/api/config` 到浏览器 | 浏览器可见 | 高德域名白名单 |
| `AMAP_SECURITY_JS_CODE` | 同上 | 浏览器可见 | 与 JS Key 配套、域名限制 |
| `AMAP_ANDROID_KEY` | Android 本机配置并嵌入 APK | APK 可提取 | 包名与签名 SHA1 |
| 腾讯地图 subkey | 小程序配置 | 小程序包可见 | 微信小程序 AppID/域名限制 |

### 当前风险

`.env.example` 当前包含看起来像真实高德 Key 的非占位值。代码无法确认这些 Key 是否仍有效。安全处理原则：

1. 立即在高德控制台轮换或吊销。
2. 检查 Git 历史、远端仓库、构建日志和聊天记录是否曾暴露。
3. 把示例值改为明显占位符。
4. 为新 Key 配置最小权限和白名单。

本轮任务按要求只修改文档，没有更改 `.env.example`；风险仍然存在。

## 4. 网络安全

### 4.1 HTTPS

小程序当前 `API_BASE_URL` 为 `https://pp.nuanzhualife.cn`。正式二维码预览和发布要求：

- 有效且完整的 HTTPS 证书链。
- 域名在微信公众平台配置为 `request` 合法域名。
- 不使用公网 IP 或非标准明文 HTTP 地址。

Node 可以在服务器内部继续监听 `127.0.0.1:5174`，由 Nginx/Caddy 终止 TLS。

### 4.2 Android 明文流量

Android 当前 fallback API 地址为 `http://124.220.73.65:5174/`，manifest 设置 `usesCleartextTraffic="true"`，网络安全配置也允许明文。这会暴露请求坐标和查询内容，并存在中间人攻击风险。正式发布应切换 HTTPS 后关闭明文流量。

### 4.3 CORS 与 API 暴露

后端当前允许 `Access-Control-Allow-Origin: *`，且没有认证、请求限流或来源校验。公开部署后，任何网站或脚本都可能消耗接口和高德配额。

短期至少应增加反向代理限流、日志和配额告警；中期评估 API 认证、来源约束和缓存。仅依靠高德 Key 配额不是滥用防护。

### 4.4 静态文件服务

`server.js` 会从项目根目录提供静态文件，并使用规范化路径和根目录前缀检查阻止明显目录穿越。当前没有 CSP、HSTS、`X-Content-Type-Options` 等安全响应头，建议由反向代理统一补充。

## 5. 日志与保留

- 后端会记录异常和部分地铁加载失败信息。
- Android debug 构建启用 OkHttp `BASIC` 日志，不记录请求体，但可能记录 URL；URL 查询参数包含坐标。
- 小程序会在控制台记录定位、地铁和更新失败。
- 当前没有正式日志保留期、脱敏规则或访问控制文档。

生产日志不应长期保存精确坐标、完整查询 URL、密钥或个人标识。反向代理访问日志若包含查询字符串，应配置脱敏或最短保留。

## 6. 隐私承诺的当前边界

### 当前有效

- 不建立用户账号。
- 不在项目数据库持久化用户位置；当前也没有业务数据库。
- 不进行后台持续定位。
- 位置用于本次查询、距离和导航。

### 尚未实现

- 用户投票、纠错和反馈。一旦实现，将新增用户提交内容、滥用治理和留存问题，必须先做隐私与安全设计。
- 隐私请求处理流程、数据导出/删除流程和第三方 SDK 清单自动化。

### 无法确认

- 线上反向代理和云平台是否记录完整查询 URL。
- 微信公众平台当前发布的最终隐私保护指引文本。
- Android 是否已向应用商店提交隐私政策。
