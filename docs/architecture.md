# 系统架构

状态：Active

## 1. 系统边界

Poopornot 包含网页、微信小程序、Android、统一 Node.js 后端和共享国内地铁厕所状态。全球 POI 支持已进入网页和微信小程序；Android 仍只使用国内接口。未传海外参数的旧请求继续进入国内兼容分支。

```text
网页（国内/海外） ──────────┐
微信小程序（国内/海外） ───┼─> server.js
Android（国内） ──────────┘      ├─> 高德 Web Service（国内）
                                ├─> Geoapify（全球地理编码、海外 POI）
                                └─> data/metro（国内厕所状态）

网页国内 ─> 高德 JS API 2.0
网页海外 ─> 同源 Leaflet 1.9.4 ─> Geoapify Tiles
微信小程序 ─> 微信 map / 腾讯地图底图
Android ─> 高德 Android SDK
```

系统没有账号、业务数据库、用户轨迹、后台管理、用户投票或持久化 POI 缓存。

## 2. 目录与职责

- `server.js`：路由、国内高德兼容链路、海外服务编排、CORS 与网页静态服务。
- `lib/http-json.js`：带超时的第三方 JSON 请求。
- `lib/provider-error.js`：供应商错误、客户端错误和密钥脱敏。
- `lib/poi.js`：WGS84 POI 规范化、距离、排序、截断、去重和坐标选择。
- `lib/providers/geoapify.js`：Geoapify Reverse、Forward 和 Places 适配器。
- `lib/global-poi-service.js`：Geoapify 地理编码、POI 查询和统一响应元数据。
- `data/global/cities.json`：六座重点海外城市的中心、国家代码、缩放与搜索硬边界。
- `data/metro/`：国内线路、站名、线路色和厕所状态，不保存坐标。
- `web-core.js`：网页查询中心、请求上下文、请求淘汰和外部导航 URL 的纯逻辑。
- `web-map-adapters.js`：高德与 Leaflet 的统一地图适配层。
- `vendor/leaflet/`：同源托管的 Leaflet 1.9.4 发行文件、图片和许可证。
- `WhereToPoop/miniprogram/services/api.ts`：小程序 API 类型和请求参数。
- `WhereToPoop/miniprogram/utils/coordinates.ts`：小程序地图与导航坐标出口。
- `WhereToPoop/miniprogram/pages/index/`：查询中心、独立结果图层、城市、长按和导航交互。
- `docs/specs/web-global-support/`：当前网页版双地图、查询中心和发布验收规则。

网页通过 `/api/config` 加载高德 JS API 配置和独立 Geoapify 瓦片凭据，并仅在首次进入海外模式时加载 Leaflet。Android 仍使用原 Retrofit 国内接口。

## 3. 查询中心与客户端状态

网页和小程序明确区分地图视口中心和正式 `queryCenter`。查询中心来源为：

- `current-location`：首次定位或重新定位；设为查询中心并自动查厕所。
- `place-search`：用户点击文字地点结果；只设定中心，等待按钮。
- `map-selection`：用户长按地图后点击“选这里”；只设定中心，等待按钮。

查询中心变化会失效旧请求并清除旧厕所、地铁、候选和 marker。切换城市只移动地图、清空 `queryCenter`，不会把城市中心冒充查询中心，也不会请求 POI。没有查询中心时，查询按钮和半径变化只提示用户先选地点。

厕所和地铁维护独立的请求序号、指纹、加载状态、结果集合与 marker：

- 首次定位成功后只自动查厕所。
- 文字地点和地图选点都保留“先选定，再点击查厕所”的两步流程。
- 已有查询中心时，切换 300 m、500 m、1 km、3 km 立即刷新厕所。
- 地铁只由专用按钮触发，固定查询 20 km 内最近 10 站。
- 同一查询中心下刷新厕所保留地铁；刷新地铁保留厕所。
- 新中心、城市切换或重新定位会同时淘汰两类旧响应。

## 4. 国内数据流

### 4.1 地点与厕所

国内地点、逆地理编码和厕所继续使用高德。未传 `region` 的旧请求默认进入国内分支，响应保留原字段并增加兼容元数据。厕所仍按 25 条分页，最多返回 `limit` 条；已有部分结果后遇到高德限流可返回 `partial: true`。

### 4.2 地铁

国内 `/api/metro/nearby` 不再逐城分页建立坐标索引。每次按钮请求只执行一次以查询中心为圆心的高德周边地铁站查询，然后：

1. 计算真实直线距离并限制在 20 km；
2. 按城市与规范化站名匹配 `data/metro`；
3. 匹配成功时使用本地 `toilet` 状态，无法唯一匹配时使用 `2`；
4. 去重、按距离排序并最多返回 10 个。

这种方式保留跨行政边界能力，同时避免启动预加载和多城市冷扫描产生的高德配额消耗。

## 5. 海外数据流

### 5.1 定位与地点

小程序先获取 GCJ-02 当前位置。坐标落在中国大陆候选范围时，优先调用高德逆地理并直接进入国内链路，不请求 Geoapify；不在候选范围或高德确认不是中国大陆时，才获取 WGS84 并调用带 `scope=global` 的 Geoapify 逆地理。海外文字搜索只在当前选定的重点城市矩形边界和国家代码内执行，`proximity` 只参与排序，后端还会过滤边界外结果。上游搜索文本补充城市当地名称以加快多语言消歧，成功结果在进程内短缓存 5 分钟。

六座城市是快捷入口和文字搜索配置，不是厕所/地铁技术白名单。六城之外的海外当前位置仍可直接查询；地图选点会继承当前国家代码。

### 5.2 厕所

```text
Geoapify Places amenity.toilet
→ WGS84 POI 规范化
→ 半径过滤、距离排序、最多 100
```

### 5.3 地铁

海外地铁直接查询 Geoapify `public_transport.subway`。结果按标准化站名和 180 m 距离保守去重，固定返回 20 km 内最近 10 站。海外站点未接入人工厕所库，统一 `toilet: 2`。

## 6. 坐标策略

| 区域 | 数据与查询 | marker | 导航 |
| --- | --- | --- | --- |
| 中国大陆 | GCJ-02 / 高德 | GCJ-02 | 网页高德路线；小程序 `wx.openLocation` 使用 GCJ-02 |
| 海外 | WGS84 / Geoapify | 原始 WGS84 | 网页 Google Maps；小程序 `wx.openLocation` 使用同一原始 WGS84 |

所有规范化 POI 显式携带 `coordinateSystem`。地图展示和导航函数只校验并返回已声明坐标，不执行无条件转换。网页和 Android 的国内坐标行为未改变。

## 7. 错误、日志与安全

- Geoapify 通过统一请求层处理超时、429、网络、5xx 和非法 JSON；逆地理与 POI 默认 4 秒，文字地点搜索单独为 6 秒。
- Geoapify 失败时返回可理解的第三方服务错误，客户端保留已有地图状态。
- 诊断日志记录请求类型、区域、供应商、耗时、数量、截断、降级和坐标系；坐标保留 5 位小数。
- API Key 不进入小程序；日志会脱敏已知密钥和 URL 中的 `apiKey`/`key`。
- 当前没有认证、服务端限流、持久化/跨实例缓存或轨迹存储；只有海外文字搜索的进程内短缓存。

## 8. 状态分类

### 当前有效

- 一个后端兼容三个客户端，旧请求默认国内。
- 微信小程序国内/海外查询中心、地图长按、独立厕所/地铁图层和外部导航。
- 网页国内高德与海外 Leaflet 双地图、统一查询中心、独立厕所/地铁图层、国内路线和海外外部导航。
- Geoapify 直连 POI、WGS84 海外链路、六城硬边界搜索。
- 国内地铁一次周边查询与本地状态匹配。

### 曾经实现但已移除

- 小程序内部步行路线与 `/api/navigation` 调用。
- 小程序启动和中心变化时预加载地铁。
- 国内地铁逐站查询，以及逐城分页建立站点坐标索引的活动链路。

### 尚未实现

- Android 海外 UI。
- 港澳台专门策略、全球城市下拉列表、用户投票、持久化/分布式缓存、认证和监控。
- 微信 Android/iOS 真机上的全球功能完整验收。

### 已放弃

- 当前阶段自建全球完整厕所数据库和客户端直线绘制地铁线路。

## 10. 网页双地图实现

ADR-0002 确定网页版按区域选择地图引擎：

```text
网页国内 ─> 高德 JS API / GCJ-02
网页海外 ─> Leaflet 1.9.4 / Geoapify Tiles / WGS84
```

`web-map-adapters.js` 统一中心、marker、视口、主题、路线和选点事件；`web-core.js` 负责区域上下文、查询中心、请求指纹和旧响应淘汰。国内行为保持高德兼容；海外复用现有后端 Geoapify 地点、厕所和地铁接口，浏览器用独立瓦片凭据直接请求 Geoapify Tiles。Leaflet 1.9.4 从 `vendor/leaflet/` 同源按需加载，不在国内启动时下载。
