# 发布流程

状态：Draft

当前仓库没有统一版本策略、CI 发布流水线或可确认的正式发布责任人。本文给出建议流程，执行前需要项目负责人确认。

## 1. 当前版本事实

- 根 `package.json`：`0.1.0`。
- Android `versionName`：`1.0.0`，`versionCode`：1。
- 旧根 README 曾写 `v1.0.0` 和 `v1.0.1`，但没有足够发布证据。
- 微信小程序版本由微信公众平台管理，当前线上版本号无法从代码确认。

在正式统一前，不应根据任一文件推断其他平台版本。

## 2. 建议版本策略

待确认后采用语义化版本 `MAJOR.MINOR.PATCH`：

- `MAJOR`：不兼容 API、数据格式或核心流程变化。
- `MINOR`：向后兼容的新功能、新城市数据或平台能力。
- `PATCH`：错误修复、数据更正和文档修复。

每个平台可以有独立构建号，但对同一次产品发布应在 `CHANGELOG.md` 中记录网页/后端、小程序和 Android 的对应版本。

## 3. 发布候选准备

1. 明确发布范围和受影响平台。
2. 从 `docs/specs/` 确认规格、计划和任务已完成。
3. 更新版本号；没有统一策略前先取得负责人确认。
4. 追加 `CHANGELOG.md`，保留全部历史。
5. 更新相关 `docs/` 和根 `README.md`。
6. 确认没有临时 API 地址、`DEBUG_METRO_CITY` 或调试 Key。
7. 确认工作区没有 `.env`、`local.properties`、keystore、证书私钥或用户数据。

## 4. 发布前门禁

### 通用

- [ ] `npm run check` 通过。
- [ ] `npm test` 和小程序 TypeScript 类型检查通过。
- [ ] 地铁 JSON 全量解析和状态校验通过。
- [ ] `docs/testing.md` 中受影响平台的人工验收完成。
- [ ] 生产 `/api/health`、厕所、地铁和逆地理编码可用。
- [ ] 高德与 Geoapify 生产 Key、配额、白名单和证书有效。
- [ ] 已准备回滚版本和配置备份。

### 微信小程序

- [ ] `API_BASE_URL` 为 `https://pp.nuanzhualife.cn`。
- [ ] `DEBUG_METRO_CITY` 为空。
- [ ] 关闭开发者工具“跳过合法域名校验”。
- [ ] 手机二维码预览通过。
- [ ] 定位权限、隐私申报、分享和导航通过。
- [ ] 六座重点海外城市、地图长按和 WGS84 marker/导航真机通过。
- [ ] OSM/Geoapify 署名和第三方隐私说明已复核。
- [ ] 结果中没有已移除的“路线”。

### 网页全球支持

- [ ] `docs/specs/web-global-support/tasks.md` 实现任务和验收已完成。
- [ ] 国内高德回归与六城 Leaflet/Geoapify 瓦片验证通过。
- [ ] `vendor/leaflet/` 已完整部署，浏览器不依赖第三方 Leaflet CDN。
- [ ] 生产 `.env` 使用独立瓦片 Key，后端 Geoapify Key 未发送到浏览器。
- [ ] Geoapify 瓦片来源限制、额度、告警和署名已复核。
- [ ] 国内内部路线和海外 WGS84 外部导航均指向正确对象。
- [ ] 保留上一版网页静态文件和后端配置回滚方案。

### Android

- [ ] JDK 17 构建通过。
- [ ] 使用生产 HTTPS API 和 release 高德 Key。
- [ ] release keystore、包名和 SHA1 匹配。
- [ ] `versionCode` 严格递增。
- [ ] 明文流量策略已评审。
- [ ] release APK/AAB 在真实设备测试。

## 5. 平台发布

### 5.1 后端与网页

1. 部署代码和 `data/metro`。
2. 保留服务器现有生产 `.env`，不要用仓库示例覆盖。
3. 重启受管理的 Node 进程。
4. 验证 HTTPS 域名和网页根路径。
5. 执行 API 与网页冒烟测试。

实际进程管理命令待确认。

### 5.2 微信小程序

1. 在微信开发者工具上传版本，填写与 `CHANGELOG.md` 一致的说明。
2. 提交体验版/审核版并完成真机验证。
3. 提交平台审核，核对服务类目、定位用途和隐私保护指引。
4. 审核通过后发布。
5. 发布后验证 `UpdateManager` 提示和新功能。

微信具体审批账号和责任人待确认。

### 5.3 Android

1. 生成签名 release AAB/APK。
2. 保存 mapping、构建日志、版本号和校验摘要。
3. 上传目标应用商店或内部分发平台。
4. 完成商店审核、隐私表单和发布。

当前没有 release signing 配置和应用商店资料，流程尚未落地。

## 6. 发布后验证

发布后 30 分钟内建议完成：

- [ ] 后端进程存活，错误日志无持续异常。
- [ ] HTTPS 证书和域名正常。
- [ ] 厕所查询结果数量与响应时间合理。
- [ ] 地铁专用按钮请求 20 km 最近 10 站，且不会自动预加载。
- [ ] 高德配额没有异常突增。
- [ ] 小程序国内外定位、城市、地点、长按、厕所、地铁和导航可用。
- [ ] Android 生产包不访问旧 HTTP IP。
- [ ] 网页国内地图和路线可用；全球支持发布后，海外底图、厕所、地铁和外部导航也可用。

## 7. 回滚与热修复

- 后端/网页：恢复上一版本代码与数据并重启；不要回退已轮换密钥。
- 地铁数据：恢复上一次已验证 JSON，并复测国内状态匹配。
- 小程序：根据微信平台能力撤回或发布修复版；旧代码包可能因缓存继续运行，需通过 `UpdateManager` 提示更新。
- Android：发布更高 `versionCode` 的修复版本。

发生安全问题时优先吊销 Key、阻断受影响入口，再处理功能回滚。

## 8. 发布记录模板

追加到 `CHANGELOG.md` 时至少写：

```markdown
## YYYY-MM-DD

- 平台：网页 / 后端 / 微信小程序 / Android / 数据 / 文档
- 变更：用户可见结果和技术影响
- 配置或迁移：没有则省略
- 已知问题：没有则写“无已知阻断问题”
```
