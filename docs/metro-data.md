# 地铁厕所数据

状态：Active

本文件是 `data/metro/` 的正式开发说明。较短的维护提示仍保留在 `data/metro/README.md`，发生冲突时以当前代码和本文为准。

## 1. 设计目标

中国大陆地铁线路、站名和厕所状态由仓库维护；站点经纬度来自每次高德周边地铁查询。这样可以避免在 JSON 中长期维护容易过期或不准确的坐标，同时让网页、小程序和 Android 共用一份厕所状态。海外地铁不写入本目录，第一版由 Geoapify 返回并统一标记为 `2`。

客户端不绘制地铁线路几何。地图底图负责显示真实线路，Poopornot 只叠加站点状态标记。

## 2. 目录结构

```text
data/metro/
  city_index.json
  <provinceSlug>/
    <citySlug>/
      line_1.json
      line_s1.json
```

示例：

```text
data/metro/jiangsu/wuxi/line_1.json
```

目录名使用英文 slug；省市中文名与 slug 的映射集中维护在 `data/metro/city_index.json`。

## 3. 城市索引

单条索引结构：

```json
{
  "province": "江苏",
  "provinceSlug": "jiangsu",
  "city": "无锡",
  "citySlug": "wuxi"
}
```

当前索引包含 52 个城市、29 个省级区域。索引项表示“目录规划和城市映射”，不表示该城市已经有人工线路数据。后端只加载实际存在 JSON 文件的城市目录。

## 4. 线路文件格式

```json
{
  "id": "wuxi_line_1",
  "name": "Wuxi Metro Line 1",
  "displayName": "无锡地铁1号线",
  "color": "#c8102e",
  "source": "AMap POI station list, manual toilet status",
  "stations": [
    { "name": "堰桥", "toilet": 1 },
    { "name": "三阳广场", "toilet": 2 }
  ]
}
```

| 字段 | 必需 | 当前用途 |
| --- | --- | --- |
| `id` | 建议必需 | 后端返回的 `lineId`；缺失时使用文件名 |
| `name` | 建议必需 | 英文或内部线路名；缺失时使用文件名 |
| `displayName` | 建议必需 | 客户端展示的线路名 |
| `color` | 建议必需 | 真实线路颜色；缺失时后端使用 `#888888` |
| `source` | 建议必需 | 数据来源说明；当前 `server.js` 读取后不会返回给客户端 |
| `stations` | 是 | 按线路顺序保存站名和厕所状态 |

站点只保存：

```json
{ "name": "站名", "toilet": 2 }
```

不要添加 `location`、`longitude` 或 `latitude`。如果坐标匹配错误，应优先改进站名规范化或后端匹配逻辑，而不是把坐标写回数据文件。

## 5. 厕所状态与颜色

| 值 | 含义 | 标记颜色 | 使用要求 |
| --- | --- | --- | --- |
| `1` | 有厕所 | 绿色 | 有可靠来源确认 |
| `0` | 没有厕所 | 红色 | 有可靠来源确认 |
| `2` | 不确定 | 橙色 `#F59E0B` | 默认值或尚未核验 |

后端遇到缺失或非法 `toilet` 值会归一化为 `2`。历史版本曾把不确定状态显示为灰色，当前三端均已改为橙色。

线路颜色和厕所状态颜色必须分开：`color` 描述线路品牌色，`toilet` 决定站点标记色。

## 7. 坐标解析与跨城逻辑

国内 `GET /api/metro/nearby` 的当前流程：

1. 只在客户端点击地铁专用按钮时调用。
2. 后端以正式查询中心执行一次高德周边地铁站查询，每页上限 25 条。
3. 规范化高德站名和 `data/metro` 站名，优先按高德返回城市匹配本地状态。
4. 仅有一个同名人工状态时可作唯一名称回退；有歧义或未匹配时使用 `2`。
5. 按站名和近似坐标去重，计算球面距离，只保留 20 km 内结果。
6. 按距离升序并最多返回最近 10 站。

空间查询以坐标为中心，不以当前行政城市限制，因此城市边界附近仍可返回邻市站点。人工状态匹配只影响颜色，不会决定站点是否出现在附近结果中。

海外流程不读取 `data/metro`：直接查询 Geoapify `public_transport.subway`，20 km 内最多 10 站，状态统一为 `2`。

## 8. 性能与缓存

- 当前活动地铁路由不建立全城市坐标缓存，也不在启动时预加载。
- 每次按钮请求国内通常消耗一次高德周边搜索；海外通常消耗一次 Geoapify Places 请求。
- 当前没有地铁服务端缓存、TTL、持久化或主动失效接口。
- `AMAP_PAGE_DELAY_MS` 继续用于国内厕所分页，不参与当前单页地铁查询。

早期“每个站单独查询一次高德”的方案会造成加载十几秒和 `CUQPS_HAS_EXCEEDED_THE_LIMIT`，现已移除。

## 9. 新增或更新数据

1. 先确认城市在 `city_index.json` 中存在且 slug 正确。
2. 创建 `data/metro/<provinceSlug>/<citySlug>/`。
3. 每条线路单独创建 `line_*.json`。
4. 按实际顺序录入站名；默认不确定状态使用 `2`。
5. 只有在可靠来源确认后才改为 `1` 或 `0`，并更新 `source`。
6. 校验 JSON 可以解析、状态只包含 `0/1/2`、线路 ID 不冲突。
7. 在目标城市和城市边界位置调用 `/api/metro/nearby` 验证状态匹配和最近 10 站。
8. 同步更新本文数据盘点和 `CHANGELOG.md`。

## 10. 数据质量规则

- 站名以高德可匹配的正式中文名称为主。
- 不把推测写成 `1` 或 `0`；无法确认时保持 `2`。
- 跨市同一线路的重复文件修改时必须同步检查另一份副本。
- 线路开通、改名、延伸或停运时需要人工复核。
- 当前没有自动数据校验脚本或 CI 门禁，属于待补能力。

## 11. 当前状态分类

### 当前有效

- 国内单一共享状态源、站名与厕所状态本地维护、坐标由高德周边结果提供。
- 20 km 附近搜索和跨城市边界显示。
- 绿色/红色/橙色状态规则。
- 海外站点实时查询，状态统一为橙色 `2`。

### 曾经实现但已移除

- 在线路 JSON 中维护 `location`。
- 前端连接站点绘制直线地铁线路。
- 后端逐站请求高德坐标。
- 后端在活动请求中逐城分页建立完整站点坐标索引。

### 尚未实现

- 全国 52 个索引城市的完整人工线路文件。
- 自动校验、来源审计、更新时间、维护人和投票更新流程。
- 对跨市重复线路的单一来源建模。
