# 全球厕所与地铁支持验收标准

状态：Draft（代码与自动化验证已完成，微信真机验收待完成）

## 0. 实施验证记录

2026-08-05 已完成 Node 语法检查、17 个自动化测试、小程序 TypeScript 类型检查、国内 API 冒烟和六座重点城市初始后端链路冒烟。随后因公共 Overpass 响应过慢，海外厕所和地铁改为 Geoapify 直连；直连参数、文字搜索城市语境、独立超时、短缓存、错误处理和供应商失败后的后端存活已由自动化测试验证。公开的新加坡市中心单次冒烟中，500 m 厕所约 1.45 s、20 km 地铁约 0.94 s；六城多轮与真机耗时仍需重新实测。

尚未完成的项目保持未勾选：微信 Android/iOS 真机 UI、地图长按/拖动/缩放、marker 与腾讯底图对齐、`wx.openLocation` 和外部地图落点、定位拒绝、生产 HTTPS 与隐私申报。自动化结果详见 `docs/testing.md`。

## 1. 验收原则

- 必须使用微信小程序真机预览或体验版验证海外地图；不能只依赖开发者工具。
- 国内回归和海外新增能力同等重要。
- 验收关注业务行为、坐标正确性、数据源降级与错误可恢复性。
- 腾讯底图是否完整绘制当地官方地铁线路颜色，不作为拉了么硬性验收项。
- 大型换乘站在不同地图中可采用站厅中心、站体中心或主入口，允许合理的小范围差异；不允许坐标系混用造成的稳定、同方向、数百米偏移。

## 3. 国内功能回归

### 3.1 首次定位

- [ ] 允许定位时，用户当前位置仍是默认查询中心。
- [ ] 国内候选位置优先使用高德逆地理，不调用或等待 Geoapify。
- [ ] 首次进入仍按现有默认半径自动查询厕所。
- [ ] 不会自动查询地铁。
- [ ] 定位拒绝时仍可进入页面并手动使用。
- [ ] 首次授权只出现一次位置权限提示，不因地图组件和业务定位并发而重复弹出。
- [ ] 临时定位失败自动重试一次，失败面板提供“重新定位”。
- [ ] 明确拒绝权限后点击“去设置”可打开微信权限设置，未授权时仍可手动使用。
- [ ] 中国大陆候选坐标的高德逆地理临时失败时不请求 Geoapify，仍保留当前位置并可查询厕所。
- [ ] 诊断日志能区分定位权限、系统定位服务、临时定位和逆地理失败，且不记录完整当前位置。

### 3.2 国内地点搜索

- [ ] 搜索仅在当前国内城市内进行。
- [ ] 搜索 UI 和候选选择体验未被无故重写。
- [ ] 点击结果后，该地点成为查询中心。
- [ ] 点击结果时清除旧厕所、旧地铁和对应 marker。
- [ ] 点击结果后不自动查询厕所或地铁。
- [ ] 用户点击“查厕所”后，才以所选地点查询。

### 3.3 半径

- [ ] 300m、500m、1km、3km 均可用。
- [ ] 切换半径后立即以当前查询中心重新查询厕所。
- [ ] 查询中心为文字结果或地图选点时，不会恢复成 GPS 位置。
- [ ] 切换半径不触发地铁查询。

### 3.4 地图长按选点

- [ ] 长按显示临时图钉和“选这里”。
- [ ] 长按本身不查询。
- [ ] 点击“选这里”后成为查询中心，并清除旧厕所、旧地铁和对应 marker。
- [ ] 点击“选这里”后不自动查询厕所或地铁。
- [ ] 用户点击“查厕所”后以选中点查询厕所；点击地铁按钮后以选中点查询地铁。
- [ ] 拖动、缩放、普通点击不触发选点。
- [ ] 国内选点与厕所 marker 在腾讯底图上没有明显系统偏移。

### 3.5 国内地铁

- [ ] 仍由专用按钮触发。
- [ ] 使用当前查询中心。
- [ ] 查询范围为 20 km，后端最多返回距离最近的 10 个站点。
- [ ] 启动、重新定位、地点选择、地图选点、厕所查询、半径切换和城市切换均不请求地铁。
- [ ] 点击地铁按钮保留已有厕所 marker，只替换地铁结果和 marker。
- [ ] 地铁状态、marker 点击和导航体验未被破坏。

## 4. 地区与城市切换

- [ ] 存在“中国大陆 / 其他地区”切换。
- [ ] 其他地区列表包含新加坡、莫斯科、东京、伦敦、纽约、悉尼。
- [ ] 切换城市后地图移动到城市中心。
- [ ] 不自动查询厕所。
- [ ] 不自动查询地铁。
- [ ] 上一城市的厕所、地铁、搜索结果和临时图钉被清理。
- [ ] 正式查询中心被清空，城市中心只作为地图视口中心。
- [ ] 此时点击“查厕所”、地铁按钮或切换半径均不发请求，并提示先选择地点。
- [ ] 用户必须通过地点搜索或地图选点形成新查询中心。

## 5. 海外首次定位

在海外真机或可控测试位置环境中：

- [ ] Reverse Geocoding 能识别国家和城市。
- [ ] 自动进入其他地区模式。
- [ ] WGS84 当前位置成为默认查询中心。
- [ ] 自动查询当前半径厕所。
- [ ] 不自动查询地铁。
- [ ] 不在六个重点城市时，技术上仍允许查询，不因“未验证城市”被拒绝。

## 6. 海外当前城市内地点搜索

每个重点城市至少测试：一个地标、一个街道/建筑、一个重名风险关键词。

- [ ] 只有点击“搜地点”才发送请求。
- [ ] 请求中按钮处于加载状态并防重复点击。
- [ ] 搜索结果被当前城市硬限制。
- [ ] 不展示其他国家或其他城市的同名结果。
- [ ] 点击结果后设置查询中心、移动地图，并清除旧厕所和旧地铁结果。
- [ ] 点击结果后不自动查询厕所或地铁，用户点击“查厕所”后才查询。
- [ ] 点击结果后无需再点“选这里”。

## 7. 海外地图长按选点

每个重点城市至少测试一个普通道路区域和一个地铁站附近区域。

- [ ] WGS84 长按坐标能正确显示临时图钉。
- [ ] 点击“选这里”后只建立查询中心，不自动查询厕所或地铁。
- [ ] 随后点击“查厕所”或地铁按钮时，均以该选中点为圆心。
- [ ] marker 与腾讯海外底图道路/建筑位置基本一致。
- [ ] 拖动和缩放不请求接口。

## 8. 海外厕所查询

每个重点城市分别测试 300m、500m、1km、3km。

- [ ] 正常情况下直接使用 Geoapify `amenity.toilet`。
- [ ] 所有结果都在所选半径内，允许少量浮点计算边界误差。
- [ ] 按距离从近到远排序。
- [ ] marker 与列表对应。
- [ ] 点击厕所可打开现有详情/导航流程。
- [ ] 最多展示最近 100 个。
- [ ] 不得把截断后的结果描述为全部结果。

## 9. Geoapify 错误与性能

通过替换请求层或真实网络验证：

- [ ] 海外 POI 请求不会先等待 Overpass。
- [ ] Geoapify 默认超时为 4 秒。
- [ ] Geoapify 429、网络错误、5xx 和非法数据返回可理解错误。
- [ ] Geoapify 结果按距离排序。
- [ ] 最多展示最近 100 个。
- [ ] 响应元数据能识别 `providerUsed=geoapify`。
- [ ] 供应商失败时不破坏已有地图状态。

## 10. 海外地铁

每个重点城市至少抽查 3 个地铁站，其中至少包含 1 个换乘或大型站点。

- [ ] 只有点击专用地铁按钮才查询。
- [ ] 使用当前查询中心，而非固定使用 GPS 位置。
- [ ] 查询范围为 20 km，后端最多返回距离最近的 10 个站点。
- [ ] 不因半径切换或厕所查询自动刷新地铁。
- [ ] 只显示站点，不把每个出入口显示成地铁站。
- [ ] 不绘制线路。
- [ ] 厕所状态为 `2`（未知）。
- [ ] 同一换乘站没有明显重复 marker 堆叠。
- [ ] 站点 marker 落在站体、站点范围或对应底图交通位置附近。
- [ ] 不存在稳定的数百米方向性偏移。
- [ ] 直接使用 Geoapify `public_transport.subway`。
- [ ] 查询地铁后已有厕所 marker 继续显示和响应点击。

## 11. 坐标与导航

### 11.1 中国大陆

- [ ] 国内地点对象标记为 GCJ-02。
- [ ] 腾讯地图 marker 使用 GCJ-02。
- [ ] `wx.openLocation` 使用 GCJ-02。
- [ ] 未因海外改造改变国内已有落点。

### 11.2 海外

- [ ] OSM/Geoapify 地点对象标记为 WGS84。
- [ ] 腾讯海外地图 marker 使用同一组 WGS84。
- [ ] `wx.openLocation` 使用同一组 WGS84。
- [ ] 没有执行 WGS84 → GCJ-02 转换。
- [ ] 莫斯科导航点与 Yandex/其他系统地图识别位置一致到合理范围。
- [ ] 东京、伦敦、纽约、新加坡、悉尼同样无系统性偏移。

## 13. 并发与状态

- [ ] 快速切换半径时，旧请求不会覆盖新请求。
- [ ] 快速点击地点结果时，最终只展示最后确认地点的数据。
- [ ] 重复点击地铁按钮不会产生重复并发。
- [ ] 离开页面后，异步响应不会写入已销毁页面。
- [ ] 切换城市后，旧城市延迟响应不会重新显示。
- [ ] 同一查询中心下刷新厕所不会清除地铁 marker，刷新地铁不会清除厕所 marker。
- [ ] 查询中心改变后，两类旧响应都不能重新写入页面。

## 14. 安全、隐私和配置

- [ ] 小程序源码和构建产物不包含 Geoapify Key。
- [ ] `.env.example` 不含真实 Key。
- [ ] 日志不含完整 Key。
- [ ] 请求参数有经纬度、半径、城市和模式校验。
- [ ] 本轮没有新增位置轨迹持久化。
- [ ] 正式公开发布前已完成 OSM/Geoapify 数据署名。
