# 功能规格：网页版全球厕所与地铁支持

状态：Active

## 1. 状态与范围

- 决策状态：产品范围与地图方案已确认。
- 实现状态：代码已实现，自动化与本地浏览器核心回归通过；真实浏览器定位、移动端长按、外部导航弹窗和六城完整 UI 矩阵仍待发布前验证。
- 适用客户端：根目录网页版 `index.html`、`app.js`、`styles.css`。
- 复用服务：现有统一后端、`data/global/cities.json`、`data/metro` 和海外 Geoapify POI 链路。
- 不适用客户端：微信小程序和 Android；本功能不得改变它们的现有行为。

本规格是网页版海外支持的实施依据。`docs/specs/global-poi-support/` 仍只描述微信小程序，不因本规格扩大范围。

## 2. 当前代码事实

当前网页版：

- 中国大陆使用高德 JS API 2.0 和 GCJ-02，海外使用同源托管的 Leaflet 1.9.4、Geoapify Tiles 和 WGS84；
- 浏览器 WGS84 定位经大陆候选判断分流，国内转换为 GCJ-02 后由高德确认，海外调用全球逆地理；
- 定位成功后当前位置成为查询中心并自动查询默认 1 km 厕所，不自动查询地铁；
- 城市切换只移动地图并清空查询中心，城市中心不参与 POI 查询；
- 文字地点和地图右键/长按选点均保留“先选定、再查询”的两步流程；
- 厕所使用 `/api/toilets`，地铁仅由专用按钮调用 `/api/metro/nearby`；两类结果和 marker 独立保留；
- 国内路线使用 `/api/navigation` 并绘制高德折线，海外导航使用原始 WGS84 打开 Google Maps；
- 结果使用左侧滚动抽屉，国内切换高德样式，海外切换 Geoapify 明暗瓦片。

## 3. 目标

1. 网页支持中国大陆和其他地区两种区域模式。
2. 国内继续使用高德底图、现有高德数据和 GCJ-02，不重写已正常运行的国内 API。
3. 海外使用 Leaflet 1.9.4、Geoapify 地图瓦片、Geoapify POI 和 WGS84。
4. 统一当前位置、文字地点和地图选点三种查询中心来源。
5. 首次定位自动查询厕所；文字地点和地图选点保留“先选定，再点查厕所”。
6. 地铁只由专用按钮查询当前中心 20 km 内最近 10 站。
7. 厕所与地铁结果和 marker 独立，查询其中一类不清除另一类。
8. 保留现有桌面布局、左侧滚动结果区、国内网页内路线和深浅色体验。

## 4. 非目标

- 不让网页版使用微信腾讯底图或 `wx.openLocation`。
- 不申请或依赖高德世界地图高级权限。
- 不把海外 WGS84 转换为 GCJ-02。
- 不改变微信小程序和 Android 的产品流程。
- 不新增全球任意城市文字搜索；第一版海外文字搜索仍限制在 `data/global/cities.json` 的六座重点城市。
- 不直接使用 `tile.openstreetmap.org` 作为生产瓦片服务。
- 不由 Node 后端代理全部地图瓦片。
- 不在本轮引入账号、收藏、历史记录或持久化位置数据库。

## 5. 地图与坐标

### 5.1 双地图引擎

| 区域 | 地图引擎 | 底图 | 数据坐标 | Marker 坐标 |
| --- | --- | --- | --- | --- |
| 中国大陆 | 高德 JS API 2.0 | 高德 | GCJ-02 | GCJ-02 |
| 其他地区 | Leaflet 1.9.4 | Geoapify Tiles | WGS84 | 原始 WGS84 |

客户端通过统一地图适配器管理中心、缩放、marker、折线、视口适配、主题和地图选点事件。业务代码不得直接假设当前地图实例一定是 `AMap.Map`。

切换区域时销毁或停用旧地图实例，初始化目标引擎，并用当前视口或所选城市中心恢复地图。地图视口中心与正式查询中心必须分离。

### 5.2 定位

1. 浏览器定位使用 WGS84 原始定位。
2. 坐标落在中国大陆候选范围时，使用高德坐标转换将定位点转换为 GCJ-02，再调用现有国内逆地理确认国家和城市。
3. 高德确认 `countryCode=cn` 后进入国内模式。
4. 其他位置保持 WGS84，调用全球逆地理进入海外模式。
5. 定位失败时不创建查询中心，打开或突出城市选择入口。

定位成功后，当前位置成为 `queryCenter`，显示实际城市并自动查询默认半径厕所；不得自动查询地铁。

### 5.3 地图选点

- 高德地图监听桌面右键和移动端可用的长按事件；Leaflet 使用 `contextmenu`，该事件同时覆盖桌面右键和移动端长按。
- 事件只建立临时点并显示“选这里”。
- 用户确认后才提交为 `queryCenter`。
- 确认会清除旧地点候选、厕所、地铁、路线、详情和 marker，但不自动查询厕所或地铁。
- 普通点击、拖动和缩放不得建立查询中心或发起 POI 请求。

## 6. 城市与地点

### 6.1 城市入口

- 顶部保持紧凑的桌面搜索条，不照搬小程序全屏城市弹层。
- 增加“中国大陆 / 其他地区”区域选择。
- 中国大陆继续允许输入城市名称并调用现有城市搜索。
- 其他地区从 `/api/global/cities` 加载六座重点城市，不允许任意海外城市作为文字搜索范围。
- 城市显示优先使用定位或选择得到的真实城市，不再固定显示“无锡”。

### 6.2 城市切换

城市切换只执行：

1. 切换地图引擎或区域模式；
2. 将地图移动到城市中心；
3. 清空正式 `queryCenter`、临时点、候选、厕所、地铁、路线和详情；
4. 显示“请先选择地点”。

城市中心不是查询中心。没有 `queryCenter` 时，查厕所、地铁和半径变化都不发请求。

### 6.3 文字地点

- 国内请求保持现有城市限制。
- 海外请求发送 `region=overseas`、`coordinateSystem=WGS84`、`countryCode` 和 `cityId`。
- 海外候选继续由后端执行国家和城市硬边界过滤。
- 选择候选后建立 `queryCenter`，清除旧 POI 和 marker，等待用户点击查询按钮。
- 地点候选 marker 只能表示候选地点，不能使用厕所图标。

## 7. 查询中心与请求规则

查询中心来源：

- `current-location`：首次定位或重新定位；自动查询厕所。
- `place-search`：文字地点结果；只选定，不自动查询。
- `map-selection`：右键/长按并确认；只选定，不自动查询。

每次提交新中心或切换城市时，必须增加请求序号，使旧地点、厕所和地铁响应失效。相同请求正在加载时禁止重复提交。

## 8. 厕所

- 保留 `300 m`、`500 m`、`1 km`、`3 km`。
- 网页默认半径继续为 `1 km`。
- 点击“查厕所”使用当前 `queryCenter`。
- 已有 `queryCenter` 时，切换半径立即重新查询厕所。
- 没有 `queryCenter` 时只提示“请先选择地点”。
- 国内不传海外参数；海外传区域和 WGS84 上下文。
- 海外最多返回最近 100 个厕所，不能描述为范围内完整清单。
- 厕所刷新保留同一查询中心下已有地铁结果和 marker。

## 9. 地铁

- 地图工具区增加独立地铁按钮。
- 取消定位、城市切换和地点选择时自动加载地铁。
- 点击按钮使用当前 `queryCenter`，固定 `radius=20000`、`limit=10`。
- 后端负责按距离排序，网页展示最近 10 站或更少。
- 国内状态继续匹配 `data/metro`；海外第一版统一为 `2`。
- `1` 为绿色、`0` 为红色、`2` 为橙色 `#F59E0B`。
- 地铁刷新保留同一查询中心下已有厕所结果和 marker。
- 结果抽屉切换到地铁列表，显示线路、距离、厕所状态和导航入口。

## 10. Marker、结果与主题

- 查询中心、临时点、地点候选、厕所和地铁使用独立 marker 集合。
- 点击厕所或地铁 marker 与点击对应结果卡片使用同一对象和坐标。
- 左侧结果抽屉一次显示地点、厕所、地铁或详情中的一种；地图可以同时保留厕所和地铁 marker。
- 地点、厕所和地铁查询完成后自动适配对应 marker 视野；不提供重复的手动“查看全部结果”按钮。
- 国内深浅色继续调用高德样式。
- 海外深浅色通过替换 Geoapify 明暗瓦片图层实现，不重新创建业务状态。
- 海外地图必须显示 Geoapify、OpenStreetMap 和适用的 OpenMapTiles 署名。

## 11. 路线与导航

- 国内保持现有 `/api/navigation` 步行路线和网页折线。
- 海外不调用高德路线接口。
- 海外“导航”使用 WGS84 目的地打开外部 Google Maps directions HTTPS 链接，并使用新标签页及 `noopener`。
- 导航目的地必须与被点击 marker/列表对象完全一致。
- 外部导航失败时保留当前结果和 marker，并显示可恢复错误。

## 12. 配置与密钥

当前已启用：

```env
GEOAPIFY_MAP_TILE_KEY=replace-with-dedicated-browser-tile-key
```

- 真实值只保存在被 Git 忽略的 `.env`，不得写入源码、文档或 `CHANGELOG.md`。
- 该 Key 专用于浏览器地图瓦片，不复用后端 `GEOAPIFY_API_KEY`。
- `/api/config` 返回浏览器需要的 `geoapifyMapTileKey`；浏览器网络面板仍可看到该值，因此它属于可公开客户端凭据，不是服务器秘密。
- 必须独立监控和轮换瓦片 Key；来源限制能力待在 Geoapify 控制台确认。
- 后端 `GEOAPIFY_API_KEY` 和 `AMAP_WEB_SERVICE_KEY` 仍不得发送到浏览器。

## 13. 非功能要求

### 13.1 性能

- 国内启动不得等待 Geoapify 地理编码或瓦片。
- Leaflet 和瓦片只在首次进入海外模式时加载。
- 切换主题只替换瓦片层，不重复请求 POI。
- 不预加载六座海外城市的瓦片或 POI。
- 必须记录并人工抽查瓦片配额；免费额度不构成生产容量承诺。

### 13.2 可用性

- 任一地图引擎或瓦片加载失败时，结果区仍可显示错误，不得让页面脚本整体退出。
- Geoapify POI 错误不得清除同一中心下已成功显示的另一类 POI。
- 窄屏下顶部控件和左侧结果区不得溢出或遮挡关键按钮。

### 13.3 安全与隐私

- 海外瓦片由浏览器直接请求 Geoapify，第三方会处理客户端 IP、Referer 和所查看的瓦片区域；正式隐私文本必须反映实际数据流。
- 地图选点、定位和搜索历史不在本项目后端持久化。
- 外部导航会离开本站，链接不得携带用户搜索历史或服务器密钥。

## 14. 验收标准

- 国内现有地图、定位、城市、地点、厕所和路线无回归。
- 国内首次定位使用实际城市和当前位置，自动查 1 km 厕所，不自动查地铁。
- 海外六城能显示 Geoapify 底图、WGS84 marker、地点、厕所和地铁。
- 城市切换只移动视口；文字地点和地图选点都保留两步查询。
- 半径只刷新厕所；地铁只由按钮查询 20 km 最近 10 站。
- 厕所与地铁 marker 互相保留。
- 海外外部导航使用选中对象的原始 WGS84。
- 明暗主题、右键/长按、“选这里”、结果滚动和署名在桌面与窄屏可用。
- 源码、文档和提交中不存在真实 Geoapify 瓦片 Key。

详细逐项验收见 `acceptance.md`。
